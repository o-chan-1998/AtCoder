ABC288 E - Wish List

商品を番号順に見て、ここまでに買った個数を状態にする。

要約 考察 実装 コード
Article

問題の要約

欲しい商品をすべて買うまでに必要な最小費用を求める。 欲しくない商品も買うことができ、何を先に買ったかによって上乗せ費用が変わる。

問題ページ: AtCoder ABC288 E - Wish List

考察

欲しい商品だけを買えばよいとは限らない。 欲しくない商品を先に買うことで、後の商品が売れ残りの中で何番目になるかが変わり、上乗せ費用を下げられる場合がある。

購入順をそのまま考えると複雑になるので、商品を番号順に見て 買うか、買わないか を決める問題として整理する。 商品 i を買うときに重要なのは、商品 i より前で何個買うことにしたかである。

前で j 個買っているなら、商品 i に使える上乗せ費用は C[i-j] から C[i] までのどれかになる。 最小費用を求めたいので、この範囲の最小値を前計算しておく。

解法方針

  1. cost[i][j] を、商品 i より前で j 個買ったときの使える上乗せ費用の最小値として作る。
  2. dp[i][j] を、商品 i まで見て j 個買ったときの最小費用とする。
  3. 欲しい商品は必ず買う。
  4. 欲しくない商品は、買わない遷移と買う遷移の両方を試す。
  5. 最後に dp[N][j] の最小値を答える。

実装の注意点

N は最大 5000 なので、O(N^2) のDPが使える。 cost[i][j] も、商品 i ごとに範囲の最小値を伸ばしながら作れば O(N^2) で前計算できる。

コード

import sys


INF = 10**30


def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    c = [0] + list(map(int, input().split()))
    wanted = set(map(int, input().split()))

    cost = [[INF] * (n + 1) for _ in range(n + 1)]
    for item in range(1, n + 1):
        current_min = INF
        for bought_before in range(item):
            c_index = item - bought_before
            current_min = min(current_min, c[c_index])
            cost[item][bought_before] = current_min

    dp = [[INF] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for item in range(1, n + 1):
        for bought_count in range(item):
            previous = dp[item - 1][bought_count]
            if previous == INF:
                continue

            if item not in wanted:
                dp[item][bought_count] = min(dp[item][bought_count], previous)

            next_cost = previous + a[item] + cost[item][bought_count]
            dp[item][bought_count + 1] = min(dp[item][bought_count + 1], next_cost)

    print(min(dp[n]))


if __name__ == "__main__":
    solve()

つまずきポイント

購入順そのものを状態にすると大きすぎる。 番号順に見たとき、上乗せ費用に影響する情報は「前で何個買ったか」に圧縮できる。

まとめ

欲しくない商品を買う選択も含めて、商品ごとに買うかどうかをDPする。 購入順の自由度は上乗せ費用の最小値として前計算し、状態数を O(N^2) に抑える。
