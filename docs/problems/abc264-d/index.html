AtCoder Study Notes

ABC264 D - "redocta".swap(i,i+1)

隣接交換の最小回数は、目標順と逆になっている文字の組の数として数えられる。

要約 考察 実装 コード
Article

問題の要約

atcoder の文字を並べ替えた文字列 S が与えられる。 隣り合う2文字の交換だけを使って atcoder にするとき、必要な最小交換回数を求める。

問題ページ: AtCoder ABC264 D - "redocta".swap(i,i+1)

考察

隣接交換では、1回の操作で隣り合う2文字の前後関係だけが入れ替わる。 そのため、目標の atcoder と比べて前後関係が逆になっている文字の組は、いつか必ず追い越しが必要になる。

逆に、逆になっている組を1つずつ直していけば目標順にできる。 したがって、答えは「目標順に対する逆転数」になる。 

atcoder の順位:
a t c o d e r
0 1 2 3 4 5 6

catredo:
c a t r e d o
2 0 1 6 5 4 3

あとは順位列の中で、左の数が右の数より大きい組を数えればよい。

実装の注意点

文字列の長さは7なので、すべての組 i < j を二重ループで見れば十分。 複雑なデータ構造は不要で、文字を順位に変換してから逆転数を数えるだけでよい。

コード

def solve():
    s = input().strip()
    target = "atcoder"

    rank = {}
    for i, ch in enumerate(target):
        rank[ch] = i

    order = []
    for ch in s:
        order.append(rank[ch])

    answer = 0
    for i in range(len(order)):
        for j in range(i + 1, len(order)):
            if order[i] > order[j]:
                answer += 1

    print(answer)


if __name__ == "__main__":
    solve()

つまずきポイント

実際の交換手順をシミュレーションしようとすると、どの交換を選ぶべきかで迷いやすい。 この問題で必要なのは手順そのものではなく、最小回数だけである。 隣接交換は「2文字の追い越し」を1回ずつ行う操作だと見ると、逆転数に帰着できる。

まとめ

文字を目標文字列での順位に変換し、順位列の逆転数を数える。 その個数が、atcoder にするための隣接交換の最小回数になる。
