ABC280 E - Critical Hit

体力ごとの期待攻撃回数を状態にし、1回攻撃した後の行き先を確率で平均する。

要約 考察 実装 コード
Article

問題の要約

体力 N のモンスターに攻撃する。 1回の攻撃では、確率 P / 100 で2ダメージ、それ以外の確率で1ダメージを与える。 体力が0以下になるまでの攻撃回数の期待値を、998244353 で割った余りとして求める。

問題ページ: AtCoder ABC280 E - Critical Hit

考察

攻撃結果の列を直接数えるのではなく、現在の体力から見た期待値を考える。 現在の体力だけ分かれば、その後に必要な攻撃回数の期待値は決まるので、 dp[i] を「体力 i から倒すまでの期待攻撃回数」と定義する。

体力 i が1以上なら、まず必ず1回攻撃する。 その後、1ダメージなら体力は i - 1、2ダメージなら i - 2 へ進む。 よって、遷移は次の形になる。 

dp[i] = 1
      + (1 - P / 100) * dp[i - 1]
      + (P / 100) * dp[i - 2]

体力が0以下ならすでに倒れているので、残りの期待攻撃回数は0である。 そのため dp[0] = 0、また i = 1 の2ダメージ先も0として扱えばよい。

小さい例

例えば N = 3, P = 10 では、2ダメージの確率が 1 / 10、 1ダメージの確率が 9 / 10 になる。

  1. dp[1] = 1。どちらの攻撃結果でも倒し切れる。
  2. dp[2] = 1 + (9 / 10) * dp[1] + (1 / 10) * dp[0] = 19 / 10。
  3. dp[3] = 1 + (9 / 10) * dp[2] + (1 / 10) * dp[1] = 281 / 100。

問題では分数をそのまま出さず、分母の逆元を使って mod 上の整数として出力する。

実装の注意点

Python では分数や小数ではなく、すべて mod 998244353 上で計算する。 100 で割る処理は、pow(100, MOD - 2, MOD) で求めた逆元を掛ける。

dp[i] は dp[i - 1] と dp[i - 2] だけに依存する。 配列で 0 から N まで順に埋めればよい。 i = 1 のときだけ dp[i - 2] が存在しないため、2ダメージ後の期待値は0として足さない。

コード

import sys

MOD = 998244353


def solve():
    input = sys.stdin.readline
    n, p = map(int, input().split())

    inv_100 = pow(100, MOD - 2, MOD)
    prob_critical = p * inv_100 % MOD
    prob_normal = (1 - prob_critical) % MOD

    dp = [0] * (n + 1)

    for hp in range(1, n + 1):
        expected = 1
        expected += prob_normal * dp[hp - 1]
        expected %= MOD

        if hp >= 2:
            expected += prob_critical * dp[hp - 2]
            expected %= MOD

        dp[hp] = expected

    print(dp[n])


if __name__ == "__main__":
    solve()

つまずきポイント

期待値の式では「今行う1回」を先に足す。 そのうえで、攻撃後の状態の期待値を確率で平均する。 また、P / 100 を通常の割り算で計算せず、mod の逆元として扱う点に注意する。

まとめ

状態を体力だけに絞ると、期待値 DP として素直に解ける。 dp[i] は、1回攻撃する分と、1ダメージ後・2ダメージ後の期待値の加重平均で求められる。
