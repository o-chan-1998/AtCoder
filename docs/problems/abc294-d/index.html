ABC294 D - Bank

「呼ばれたが、まだ受付に行っていない人」のうち最小番号を、イベントごとに管理する。

要約 考察 実装 コード
Article

問題の要約

銀行で、まだ呼ばれていない人を順に呼ぶイベント、呼ばれた人が受付へ行くイベント、 まだ受付へ行っていない人のうち最小番号を出力するイベントを処理する。

問題ページ: AtCoder ABC294 D - Bank

考察

出力で必要なのは、呼ばれた人全員ではなく 呼ばれたが、まだ受付に行っていない人 の最小番号である。 イベント1で呼ばれる番号は必ず 1, 2, 3, ... の順なので、 次に呼ぶ番号を1つ持てばよい。

受付へ行った人は二度と候補にならない。 そのため、done[x] で受付済みかを持ち、答え候補のポインタを 受付済みでないところまで進めれば、イベント3に答えられる。

解法方針

  1. next_person を、次にイベント1で呼ぶ番号として持つ。
  2. done[x] を、人 x が受付へ行ったかとして持つ。
  3. イベント1では next_person を1つ進める。
  4. イベント2では done[x] = True にする。
  5. イベント3では、最小候補が受付済みなら進め、止まった番号を出力する。

実装の注意点

set の min を毎回使うと、集合の大きさに比例して重くなる。 番号は小さい順にしか呼ばれないので、答え候補を指すポインタで十分である。

コード

import sys


def solve():
    input = sys.stdin.readline
    n, q = map(int, input().split())

    next_person = 1
    answer_candidate = 1
    done = [False] * (n + 2)
    called_until = 0
    answers = []

    for _ in range(q):
        event = list(map(int, input().split()))

        if event[0] == 1:
            called_until = next_person
            next_person += 1
        elif event[0] == 2:
            x = event[1]
            done[x] = True
        else:
            while done[answer_candidate]:
                answer_candidate += 1
            answers.append(str(answer_candidate))

    print("\n".join(answers))


if __name__ == "__main__":
    solve()

つまずきポイント

イベント3は、再度呼ぶだけで受付済みにはしない。 そのため、同じ人がイベント3で複数回出力されることがある。

まとめ

出力候補を「呼ばれたが未受付の人」に絞り、受付済みフラグと最小候補ポインタで管理する。 番号が順にしか呼ばれない性質を使うと、複雑なデータ構造なしで処理できる。
